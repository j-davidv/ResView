## Correction and failure checks

The worker's synthetic recovery suite uses the production provider switching logic with isolated in-memory records. It verifies changed document bytes, rejected extraction, changed official document links, version-pinned announcement changes, explicit profile disabling, source outages, failed uploads, incomplete HTTP responses and repeat scans. Failed validation exposes no usable names URL; superseded versions cannot be reactivated. Source outages and upload failures for an unchanged validated version preserve last-good checking while health becomes stale and the last-success timestamp stays unchanged. Once a corrected document validates, the old version is superseded before upload; a failed correction upload leaves the new version unavailable. Upload/read-back refusal tests verify that availability is never activated on failure.

Changed pinned mappings produce revocation-only observations for the previously reviewed selections, remain in review, and prevent an older announcement from becoming the latest result. They do not publish a new unreviewed association. For same-day releases, the newest official index entry wins the tie. A profile with `disabled: true` revokes its reviewed original without downloading or uploading names. Removing the profile alone intentionally preserves an unchanged, previously validated list.

Flutter tests verify that learning of a newer version or a same-version revocation blocks saved-list use. Successful invalidation persists across a new `ListStore`; temporary storage failures retain the known revocation in memory, including failures before saved-file enumeration. The active checking screen resets when availability changes. A metadata outage retains the last-good checking state with a stale warning. A device that has not learned of a correction cannot infer it offline. If revocation cannot be persisted, the in-memory block lasts for that process; the visible error requires retrying before offline reuse after restarting.

Final local checks: 54 worker tests, 34 Flutter tests and `flutter analyze` pass. Real malformed-PDF and revocation/republication regressions verify parser failure handling and immutable checksums across revocation. Unavailable records retain the checksum without a usable names URL, so disabling/re-enabling cannot authorize changed bytes under the same document version. The private real-document replay passes its 37 refusal checks and 17 worker replays; the original PDF is unchanged and excluded from Git. These are local failure-injection checks, not induced production PRC or Storage outages. Live Firestore transaction conflict/retry injection and physical disk exhaustion were not performed.
