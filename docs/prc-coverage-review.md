## Review procedure

1. After each live monitor attempt, inspect its `document-review/coverage.json` artifact. It records publication links, current document versions, availability/reasons, source health and unresolved mapping issues. A failed scan can leave a useful last-good inventory; its timestamp is not evidence of a successful source refresh. Inventory generation only reads Firestore.
2. The maintainer reviews the latest inventory at least daily and after a failed run, new release or correction. Keep unresolved items open. Save evidence locally before the seven-day artifact expires. The hourly trigger remains subject to the separate task 8 scheduler acceptance item; a configured cron is not proof that it fired.
3. For permitted acquisition, manually dispatch the monitor with `review_documents=true`. Set `live=false` for a read-only acquisition; use `live=true` for the normal metadata/revalidation scan. Acquisition follows owner capabilities and existing source rules, encrypts originals with repository variable `PRC_REVIEW_CERTIFICATE`, and never approves or activates a list. Qualified links from combined announcements are candidates only. Failed or ambiguous acquisitions keep checking unavailable and retain the official publication link.
4. For each new or corrected version, repeat the [format-validation procedure](format-validation.md). Preserve the original/source chain; independently compare all rows and inspect rendered samples; review every selection/category association. Register an exact SHA-256 profile only after the evidence and refusal checks pass. A profile for one announcement or version never approves another release.
5. Upload an immutable asset with the private publisher, verify its public bytes/hash and Flutter decoding, then activate it transactionally. Update the encrypted profile set without dropping already approved profiles. Run hosted revalidation and verify availability with an unauthenticated client. Any new observed original hash requires another independent review.
6. Keep unsupported versions unavailable. To suspend an approved faulty profile, set its private `disabled` flag and run the worker; simply removing a profile deliberately preserves unchanged last-good data. Retain correction history and original evidence.

Private reproducibility: use `.development/task9/validate.py`, `publication_test.dart` and `public-read.cjs` with the existing local worker packages. The recipient private key must stay private; only the PEM certificate belongs in `PRC_REVIEW_CERTIFICATE`. Losing the key makes retained encrypted artifacts unreadable, so preserve the reviewed local originals and key together in private storage.

## Remaining limits

Full 2026-onward coverage is incomplete. Restricted/unusable acquisitions and ambiguous associations have not been approved. Scanned, wrapped-name and multiple-section layouts have no new adapter. Names are preserved as published; no reliable surname/given-name components are inferred. A published-name match does not establish identity, and an absent name does not establish failure. Scheduled-event acceptance, physical-phone verification of these three additions, complete privacy acceptance and delivery remain separate checklist work.
